## What's built

| Piece | File | What it does |
|---|---|---|
| Records | `pipeline/db.py` | SQLite `db/app.sqlite` with the seven tables from ARCHITECTURE.md (described below). |
| Nightly prices | `pipeline/daily.py prices` | Re-fetches the last 14 days from yfinance for every symbol in the price plan (about 6,350), rebuilds raw prices from the window's splits, and replaces those (source, symbol, date) rows in their year files. |
| Nightly checks | `pipeline/daily.py checks` | Applies the M1 rules (sanity, unexplained 40% moves) to the new days, plus a **block** if under 95% of current index stocks have a price for the latest trading day. |
| Spot check | `pipeline/daily.py spotcheck` | Checks 20 stocks a day against Tiingo over the window: closes within 0.5%, and splits and dividends date by date (M1's carry-forward). |
| Backups | `pipeline/backup.py nightly` | Ingests the inbox, takes snapshots, and writes a text export (described below). |
| Restore test | `pipeline/backup.py restore`, `restore.yml` | Checks the newest snapshot (described below). |
| Live universe | `pipeline/universe.py` | Builds the monthly universe (described below). |

**Records (`db/app.sqlite`):**

- Tables: trades, corrections, verdicts, buy_snapshots, panel_opinions, alerts, experiments.
- **Every table is append-only:** triggers reject UPDATE and DELETE, so a fix is a new row in corrections.
- Verdicts carry a **hash chain** (each row stores a fingerprint of the one before), and `verify_chain` finds the first altered row.
- Trades from the Worker's `inbox/*.json` are added once each (rerunning is safe), and bad files are rejected loudly. The Worker itself comes in M6.

**Why the 14-day price window is safe:** raw prices only change on or after a split, so a 14-day window catches every change, and rerunning gives the same result.

**Spot check details:**

- The pool is **150 index stocks, fixed for the month** (drawn with the month as the seed), so every pool stock is checked within 8 trading days.
- That uses at most 150 of Tiingo's 500 symbols a month.
- A close more than 0.5% off is quarantined. Split and dividend differences are logged, since spin-offs are encoded differently by the two sources (see M1).

**Backups:**

- Snapshots go to `backups/daily/<date>.sqlite` (the newest 30 kept) and `backups/monthly/<yyyy-mm>.sqlite` (kept indefinitely).
- A CSV text export of every table is pushed nightly to the private `StockWatchBackups` repo, using a deploy key with write access to that repo only (secret `BACKUP_DEPLOY_KEY`).
- If R2 has no database and the run isn't flagged `first_run`, it refuses to start a fresh, empty one.

**Restore test:** the newest snapshot from R2 is checked for SQLite integrity, the verdict hash chain, and row counts against the text export in the backup repo.

**Live universe** (`market/universe/<yyyy-mm>.parquet`):

- NYSE or Nasdaq, common stock.
- US companies: files 10-K/10-Q XBRL, with one in the last 18 months (ADRs file 20-F).
- Price above $5.
- Market value (close × XBRL shares) above $300M.
- Median daily dollar volume of $1M or more over 20 days. **The plan gives no number, so $1M is a starting point to revisit.**

**SEC refresh nightly:** `submissions.zip` and `companyfacts.zip` are re-read in full each night, about 5 minutes. Simpler than per-company updates, and the bulk files are already rebuilt each business evening.

## Schedules

All times UTC. Every job that writes to R2 shares one queue (`concurrency: r2-writer`).

| Workflow | When | Does |
|---|---|---|
| `nightly` | Tue to Sat 01:17 (Mon to Fri 8:17 pm CDT / 7:17 pm CST) | SEC refresh, 14-day prices, checks, spot check, records and backups, text export, run log in `logs/runs/<date>.json` |
| `backfill` | First Saturday 06:17 | Membership, SEC, ticker map, reconcile (fails on unreviewed disagreements), fundamentals |
| `prices` | First Saturday 09:17 | Full price rebuild (new listings get history), identity checks, live universe |
| `restore` | First Saturday 12:17, and by hand | Restore test |

The monthly ones run every Saturday, but a gate job skips them unless the date is the 1st to the 7th.

## Not in M2 (per the plan)

- Scores and verdicts: M3. The nightly job has no verdicts to block yet; a block day is recorded and fails the run loudly.
- Daily summary by email or Discord: M5. For now it's the GitHub run summary and `logs/runs/<date>.json`.
- The Trade Worker that writes `inbox/`: M6.
